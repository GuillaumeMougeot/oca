# Remotes: any machine as a model server

**Status:** OPEN. Built on branch `remotes`; the user tests it on a DGX Spark before it reaches `main`.

## Question
How can oca use a DGX Spark, or any other machine, beside UCloud, switch between them transparently, and stay as easy to set up as `oca cluster up`?

## Decisions (2026-11-01, with the user)
- `oca remote` replaces `oca cluster`, without an alias. A remote is UCloud, a machine reached over SSH, or a URL.
- A default server, as Claude Code has a default model. Plain `oca` uses it, `oca -r <name>` another for one session, and `oca remote default` changes it. OpenCode lists one model per server; `ctrl+x m` switches mid-session.
- When a session's server stops, the next one replies, with a one-line note; the user chose this over stopping. The order is the requested server, the default, the other remotes by context window, then local.
- A server with a smaller context window stands in with the latest messages that fit, and the session keeps its whole history. Only a stand-in trims: OpenCode compacts for the server it asked for, and oca's token estimate (3 characters per token) runs high, so trimming there would drop context that fits.
- Like an installer, `oca remote add` asks whether to install oca on an SSH machine for you only or for all its users. The install for all users lives in `/opt/oca`, which an admin creates once for a group. Whoever adds the machine next finds it and joins its server. Shared servers stop when idle, like UCloud's.

## Check (2026-11-01)
This workstation cannot SSH into a second machine, so a stand-in `ssh` ran the remote commands here, with another home and no GPU, and forwarded ports. Through it:
- `oca remote add` installed oca for all users from the branch in 35 s: probe, question, install, marker, and group-readable key files.
- `oca remote up --wait` was ready in 12 s (CPU, with the model already in the page cache).
- An OpenCode run went through `oca/spark`, and a 73k-token conversation was trimmed into 32k. This was before the rule above limited trimming to stand-ins.
- With the server stopped, the next reply came from local with "spark is not answering, so local replies". Once the server was back, the note said "spark replies again".
- A second client found the shared install and joined the running server instead of starting one.

Fixed along the way: trimming on the requested server, the context shown for a stopped SSH remote, and joining a shared install outside `/opt/oca`.

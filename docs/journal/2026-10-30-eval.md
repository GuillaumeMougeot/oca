# Eval

**Status:** OPEN. Qwen3.8-Flash-Next solves 85 to 91% at any effort, in about 10 s per exercise. Nearly every failure is a mistyped path the run is not allowed to follow, so this set is too easy to rank models: harder tasks are next.

## Question
How often does oca's agent solve real exercises, per model and effort, and how fast?

## Protocol
- **Tasks:** the 34 Python exercises of Aider's polyglot benchmark, pinned at commit 7e0611e. These are Exercism's hardest Python exercises (MIT); they are downloaded at run time, not vendored.
- **Setup:** each exercise is copied without `.meta/` (the reference solution) and `.approaches/` (solution write-ups). The agent gets the instructions and the stub, and may run the tests under oca's usual permission rules.
- **Scoring:** after the agent stops, the original test file is restored and decides pass or fail. One attempt, at most 15 min.
- **Difference from Aider:** Aider hides the tests on the first try and shows failures on a second. Here the agent sees the tests, as in real work, so scores are not comparable with Aider's leaderboard.

## Hypothesis (written before any run)
- Flash-Next at its default effort: 70 to 90%, under a minute per exercise.
- Flash-Next with thinking off (`none`): 20 points lower. (Measured: 6 points lower.)
- The local CPU model: 50 to 70%, minutes per exercise.

## Results (2026-10-30, the maintainer approved running the benchmark locally)

| Model | Effort | Passed | Median | Max |
|---|---|---|---|---|
| Qwen3.8-Flash-Next, 1×B200 | none | 29/34 (85%) | 7 s | 36 s |
| Qwen3.8-Flash-Next, 1×B200 | low | 30/34 (88%) | 12 s | 37 s |
| Qwen3.8-Flash-Next, 1×B200 | high (its `xhigh`) | 31/34 (91%) | 11 s | 102 s |

- **Failures:** 11 of the 12 across the three runs end within 4 s on a rejected read. The model guesses a wrong absolute path outside the exercise, such as `book_store/` for `book-store/`; an unattended run rejects it, and the run ends. A person at the prompt would see the bad path.
- **Effort:** it barely matters here. With the tests visible, these exercises are close to solved; the hypothesis expected a 20-point drop without thinking, and the drop was 6.
- **Next:** harder, multi-file tasks to separate models and efforts; the local CPU model; DeepSeek when two B200s are free.
- **First attempt, 0/34:** the harness started OpenCode with the working directory set but `$PWD` still pointing at the oca repo. OpenCode takes its project from `$PWD`, so every read of the exercise was "external" and rejected. The harness and `agent.launch` now set `PWD`.

## Harder suite: oca's own history (`eval/run.py --suite history`)
- **Tasks:** 9 commits that changed code and tests. Each starts from the commit's parent, exported without git history, with the commit's tests copied in. The request is the commit message.
- **Validity:** `--check` confirms that all 9 fail as given and pass with the commit.
- **Size:** from a 19-line serve-script fix to the 275-line router.

**Hypothesis** (written before the run): Flash-Next at high effort solves 4 to 6 of 9, at 1 to 5 min each. The router (848cc1f) and the sharing change (24f112d) are the hardest.

**Result, history suite at high:** 7/9 (78%), median 88 s, max 150 s. Solved: the sharing change, macOS support, effort, permissions and three smaller fixes. Failed: the router (two of its tests still failing) and `oca web`. Both ended on one rejected action: a probe script in `/tmp`, and a web fetch of OpenCode's docs.

## Unattended runs refuse instead of asking
In a non-interactive run, OpenCode rejects what would ask, and a rejection ends the run. A denial is an error the model reads and works around: with `sudo` denied, the agent explained and carried on. So `opencode run`, from `oca run -- run …` and from the eval, now gets a config where every "ask" is "deny" (`agent.config_path(unattended=True)`). Interactive sessions still ask.

**Hypothesis** (before re-running both suites at high): polyglot rises from 91% to 97 to 100%, and history from 7 to 8 or 9 of 9.

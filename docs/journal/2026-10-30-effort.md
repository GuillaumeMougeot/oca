# Effort

**Status:** RESOLVED. OpenCode's model variants are the equivalent of Claude Code's effort. oca offers five levels on `oca/auto` and translates them for each model.

## Question
Claude Code has an effort setting that changes results a lot. Does OpenCode have one?

## Findings (2026-10-30)
- OpenCode has model variants: `ctrl+t` cycles them, and `opencode run --variant` picks one. A custom provider's model only has the variants its config defines, and oca's defined none.
- A variant's `reasoningEffort` reaches the server as `reasoning_effort`, and extra keys such as `chat_template_kwargs` pass through. Checked with a capturing proxy.
- Each model speaks its own dialect:

| Model | Effort values | Thinking off |
|---|---|---|
| Qwen3.8-Flash-Next | `low`, `medium`, `xhigh` (default); it rejects `high` and `max` | `enable_thinking: false` or `none` |
| DeepSeek-V4.1-Flash (vLLM's encoder) | 1 to 100, or `low` 50, `high` 75 (default), `xhigh`, `max` 100 | `none` |
| Qwen3.6-35B-A3B (local chat template) | none | `enable_thinking: false` |

## Design
- oca's levels: `none`, `low`, `medium`, `high`, `max`.
- The router rewrites each request in the backend's terms, inside `chat_template_kwargs`: `none` becomes `enable_thinking: false`, and the other levels become the model's own value from `ClusterModel.efforts`.
- A model without graded effort keeps its default thinking.

## Measurement
Flash-Next on one B200, with one counting question (the answer is 400):

| Effort | Tokens | Time | Answer |
|---|---|---|---|
| none | 4 | 0.1 s | 667 (wrong) |
| low | 275 | 0.7 s | 400 |
| medium | 271 | 0.7 s | 400 |
| xhigh | 378 | 1.0 s | 400 |

Through the router, `--variant none`, `low` and `max` all ran; without the translation, `max` had been rejected. With thinking off, the agent reached for a shell command to compute the answer instead.
